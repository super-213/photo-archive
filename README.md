# 片隅 · Photo Archive

品牌标识为「片隅.」，英文副标为「A PERSONAL PHOTOGRAPHY COLLECTION」。「所见」展示精选摄影系列，「所藏」保存全部公开摄影档案。

Logo 原始素材位于 `docs/pianyu-logo-assets/`。运行时 SVG 和 PNG 放在 `public/`，前台、后台、错误页与分享图统一使用该标识；深色大图浏览器使用反白版。浏览器标签页的 `src/app/icon.svg` 和兼容图标 `favicon.ico` 均使用原始透明底浅色标识，不添加底色或主题切换。`apple-icon.png` 用于手机主屏幕，安装图标保留原有背景。更换素材时同步更新部署副本，执行 `npm run pwa:icons` 重新生成这些图标，并递增 Service Worker 的缓存版本后重新构建。

本地运行的个人摄影作品集。使用 Next.js App Router、TypeScript、SQLite、Better Auth 和 Sharp。包含公开作品集和管理员后台，当前保留 18 张 Unsplash 样例照片与 3 个样例系列。

## 首次运行

需要 Node.js 22.13 或更高版本，建议使用当前 LTS 版本。版权元数据写入使用随依赖安装的 ExifTool，运行环境需要 Perl。

```sh
npm install
cp .env.example .env.local
npm run db:init
npm run admin:create
npm run dev -- --port 3000
```

`admin:create` 在终端中询问邮箱与密码，密码输入隐藏，至少 12 位。管理员通过本机命令创建，站点公开注册已关闭。打开 `http://127.0.0.1:3000/admin` 登录。将 `3000` 换成自己选择的空闲端口。

`db:init` 创建数据库和版本化表结构，读取样例照片并生成展示图。再次运行会保留已有照片的手动编辑、公开状态和系列编排。

开发模式使用 Webpack 轮询监听，兼容当前 macOS 环境的文件监听限制。

## 正式部署与日常启停

脚本支持 macOS 和 Linux，使用本机 Node.js、npm 与 `ps`。首次安装依赖后，在项目目录执行启动脚本。

```sh
npm ci
./start.sh
```

启动脚本先检查并迁移数据库。缺少管理员时，在终端交互输入邮箱、密码和确认密码，密码输入隐藏，至少 12 位。已有管理员会直接复用。随后询问部署端口，默认显示上次保存的端口，首次默认 3000，并检查端口可用性。确认后构建生产版本，在后台监听 `0.0.0.0`，支持本机和局域网访问，关闭当前终端后服务继续运行。

| 脚本 | 用途 |
|---|---|
| `./start.sh` | 检查管理员、询问端口、构建并后台启动 |
| `./stop.sh` | 自动读取运行记录，停止对应服务并释放端口 |
| `./status.sh` | 显示进程状态、PID、端口、访问地址、启动时间和日志路径 |
| `./restart.sh` | 停止旧服务、重新构建并启动，沿用上次端口 |

修改代码或环境配置后执行 `./restart.sh`，会自动完成构建和重启，无需再次输入端口。构建失败时服务保持停止，修复后再次运行重启脚本即可。重复启动会显示已有服务，重复停止也可直接执行。脚本会核对进程身份，并对启停操作加锁。

`.env.local` 保存 `PHOTO_ARCHIVE_PORT` 与管理员邮箱，文件权限为 `600`。管理员密码以哈希形式保存在数据库。启动脚本在确认或创建管理员后清理环境文件里的旧初始密码配置。该文件已加入 Git 忽略，既有的域名、数据目录和其他配置会保留。

`.runtime/server.json` 保存当前进程和上次端口，`.runtime/server.log` 保存后台运行日志。运行目录已加入 Git 忽略。可使用以下命令查看最近日志。

```sh
tail -n 100 .runtime/server.log
```

启动脚本会自动初始化业务表和认证表。需要导入示例照片时，可单独运行 `npm run db:init`。

## Cloudflare Tunnel

首次部署前，可复制 `.env.example` 为 `.env.local`，取消 `BETTER_AUTH_URL` 前的注释并填写实际访问域名，例如 `https://photos.example.com`。启动脚本已经生成环境文件时，直接编辑其中的域名配置。首次运行使用启动脚本，已运行的服务修改域名后执行 `./restart.sh`，随后从该域名登录管理后台。

```sh
./start.sh
```

将已有 Cloudflare Tunnel 的目标服务设为 `http://127.0.0.1:3000`，与实际端口一致。生产服务监听 `0.0.0.0`，同时支持正式域名、本机 `http://127.0.0.1:端口/admin`、`http://localhost:端口/admin` 和 `http://本机局域网IP:端口/admin`。局域网 IP 自动识别本机网卡上的 `10.*`、`172.16–31.*`、`192.168.*` 地址，IP 变化后重新登录即可。

保留 `BETTER_AUTH_URL` 中的正式 HTTPS 域名。不同访问地址分别登录，使用相同的管理员账号；HTTPS 域名的 Cookie 保留 Secure 属性，内网 HTTP 地址使用仅限该主机的 Cookie。保存、上传等写请求必须来自当前访问地址，其他域名和非本机的局域网 IP 不会被加入允许列表。开发服务仍只监听 `127.0.0.1`，`admin/admin` 仅限开发模式。

环境变量由 Next.js 和本地初始化命令从 `.env.local` 读取。`PHOTO_ARCHIVE_DATA_DIR` 可指定其他本地数据目录。

## 管理流程

1. 在 `/admin/photos` 多选上传照片。单张最大 256 MiB，最多 2.4 亿像素，支持单帧 JPEG、PNG、WebP、AVIF、TIFF。
2. 上传后照片进入草稿，系统提取基础 EXIF 并生成缩略图、网格图和大图展示版。上传结果逐张反馈，失败项可以重试。
3. 点选照片，编辑标题、替代文本、日期、地点、器材、题材和标签，然后设置公开状态。
4. 在 `/admin/projects` 创建系列，选择布局类型并从媒体库加入照片，设置封面，调整布局和组内照片顺序，使用实时预览查看效果。
5. 将系列状态改为发布并保存。系列至少需要一张照片，封面来自当前系列，且关联照片均已公开。

同一张照片可加入多个系列，系列内排序相互独立。重复上传按照文件内容识别，沿用已有记录和人工修改信息。删除系列只删除系列及关联，照片仍保留在媒体库。

将照片改为草稿或私有时，相关已发布系列会自动退回草稿。再次公开照片后，可在后台检查并重新发布系列。保存会检查记录版本，并发编辑发生冲突时会提示重新打开。

照片信息通过 `PATCH` 只提交和更新有变化的字段；未修改的标签不重写，没有修改时不发送保存请求。修改信息不会重新上传或压缩图片。

## 从服务器文件夹自动导入

站点服务启动后会自动扫描项目根目录的 `imports/`，不需要打开浏览器。把外接硬盘中的照片或整个子文件夹复制进去即可，例如：

```text
photo-archive/
  imports/
    旅行照片/
      海边.jpg
      日落.tif
```

每轮扫描间隔约 3 秒，同一文件的大小和修改时间至少保持 6 秒不变后才处理。程序逐张生成展示图、提取 EXIF、写入已配置的版权信息，并作为草稿加入照片管理。大照片或大批次会需要更长的处理时间。文件在扫描或快照复制期间发生变化时，会重新等待稳定；复制中断后可继续复制，文件变化后自动重试。

- 支持 JPEG、PNG、WebP、AVIF、HEIF/HEIC 和 TIFF 扩展名，单张最多 256 MiB、2.4 亿像素，实际解码支持与后台上传相同。忽略隐藏文件、其他文件类型和符号链接。
- 内容相同的照片沿用媒体库已有记录，不覆盖标题、标签、公开状态或系列编排。导入记录保存在数据库，服务重启后不会重复处理未变化的文件，意外中断的任务会在后续扫描中恢复。
- **成功导入或确认重复后，自动删除导入目录中的源图片。** 媒体库独立保存三档展示图，删除导入源图片不影响照片展示；开启原图下载时另存原件，关闭时只保留展示图。失败文件和处理期间发生变化的文件会保留；不会删除子文件夹、隐藏文件或其他类型的文件。重启后的扫描也会清理此前已成功导入且未变化的源图片。导入目录中的照片已加入 Git 忽略。
- 在后台“照片管理”的“文件夹导入”区域查看实际目录，点击“刷新导入结果”更新照片列表、处理数量和失败原因。`imports/导入记录.json` 保存最近 100 条记录，完整历史在数据库中；生产运行日志也记录逐张结果。

可在 `.env.local` 中设置 `PHOTO_ARCHIVE_IMPORT_DIR=/绝对路径/导入目录`，修改后重启服务。自定义导入目录同样会在导入成功后自动删除源图片，请使用待导入副本目录。目录不能与 `public/` 或数据目录重叠。设置 `PHOTO_ARCHIVE_FOLDER_IMPORT=false` 可关闭自动扫描。

服务未启动时，也可以手动扫描；重试未变化的失败文件时加上 `--retry`：

```sh
npm run photos:import
npm run photos:import -- --retry
```

手动扫描同样等待文件稳定并记录处理结果。新增文件通常会在数秒后开始处理，正在复制或持续修改的文件留待下一次扫描。

## 编辑式排版与检索

系列支持全宽、居中、双图、错位双图、一大一小、三联六种排版。后台按布局分组编辑，整组排序与组内照片排序分别保存。点击“向此布局添加照片”可继续填充当前组，选择“新增布局类型”并从媒体库添加照片可开始新组。缩小容量会自动拆分，照片按原顺序进入后续组。未填满的组合按现有照片展示，单张组合居中显示。

“预览排版”即时展示当前编辑内容，预览中的照片也可进入大图。保存系列后，公开页面按保存的布局分组展示。数据库迁移保留旧系列的顺序、封面、状态和说明，并将原有全宽、居中、双图编排兼容为分组。

「所藏」默认收起题材面板，通过“全部题材”文字与调节图标入口展开全部、风光、街拍、旅行、人文、汽车、模型七个题材选项。展开时在原工具行内用题材选项替换数量文字，使用淡入过渡，关闭后恢复数量文字。选择后面板自动收起，入口显示当前题材，支持 Esc、点击外部和键盘切换焦点关闭。题材通过 `category` 参数同步 URL，支持刷新、浏览器前进后退和分享。所藏按题材在服务端查询，首批展示 24 张，通过“加载更多照片”继续浏览，加载失败可重试。每批独立维持瀑布流排版，追加照片时保留已有批次的位置。旧链接中的年份、地点、机身、镜头与关键词参数会被忽略，切换题材时自动清除。

大图支持 1–4 倍缩放、滚轮、双击、拖动和平移边界约束，并实现双指缩放手势。键盘 `+` / `-` 缩放、`0` 复位，`Shift` 加方向键平移，单独左右方向键切图，`Esc` 关闭。切图会恢复到适应屏幕的比例。EXIF 面板按需展示，缺少信息的字段显示待录入。

鼠标悬停、键盘聚焦或按下系列封面时，会完整预取系列页面，并按详情排版预加载首组最多两张图片。照片入口会提前加载大图浏览组件；大图在测量实际展示区域后选择尺寸，当前照片载入完成后再于空闲时低优先级依次预取前后各一张，切图或关闭后取消尚未开始的任务。省流量模式和 2G 网络跳过这些额外预加载。

图片根据显示尺寸与缩放比例选择派生图，保留尺寸占位。大图先显示缩略预览，再展示清晰图；首次载入使用短淡入，已完成载入或本次浏览中已加载的同一图片地址直接显示。加载失败提供提示，减少动态效果偏好会停用动画。手机视口已做响应式检查，双指缩放和滑动手势仍需真机体验验收。

## 展示画质与原图

网页按显示尺寸和缩放倍数选择最长边 420、840、2560 像素的展示图，三档均使用 WebP Quality 90 有损编码并保留 ICC 色彩配置，在画质和文件体积之间取舍，以加快图片加载。每张照片固定保存三档展示图，是否另存 `original` 由 `PHOTO_ARCHIVE_ORIGINAL_DOWNLOAD` 控制，默认 `false`。数据库始终保留源文件 SHA-256 指纹以识别重复照片，并保留提取的拍摄信息；上传与导入的临时文件在处理完成后删除。

展示档位为 `thumbnail`（420）、`preview`（840）、`lightbox`（2560）。普通页面与后台编辑区最多使用 840 像素预览，大图浏览器才可按显示大小和缩放选择 2560 像素版本；宽屏和高像素密度设备上的普通预览可能较软，可点开大图查看细节。1440 像素的 `grid` 不再生成，旧的 `/grid` 和 `/grid.webp` 链接转用预览图且不进入共享缓存。

手机和小网格会优先选择较小尺寸，大图先显示缩略预览。Quality 90 不等同于无损，具体文件体积和观看效果取决于照片内容。编码版本已升级，重建命令会将旧版无损展示图转换为 Quality 90。

已有照片可执行以下命令，检查并更新展示图。在确认三档展示图完整可用后，删除旧的 `download`、`grid` 文件及其数据库记录；关闭原图下载时也会删除 `original`。

```sh
npm run media:rebuild
```

重建按编码版本跳过已更新照片，每张展示图写入完成后原子替换，保留照片元信息与系列编排。缺失的小尺寸图可从现有 2560 像素大图补齐；大图也缺失时会提示重新导入源照片，重新导入按指纹沿用已有记录。版权配置更新直接修改现有 WebP 的元数据，不重复压缩图片。`db:init` 会同步升级已有样例照片。

已有三档均有效时不会重新编码，只清理历史媒体文件，照片信息和公开状态保持不变。关闭原图下载并完成清理后，系统无法从展示图恢复完整原图；重新开启下载时会提供现存最大的展示图，重新导入同一源照片可补存原图。CDN 规则文件已精简为三档；此前包含 `grid.webp` 的规则可同步更新，旧地址的源站响应会明确禁止 CDN 缓存。

## 原图下载与保存开关

在 `.env.local` 中配置，修改后执行 `./restart.sh` 生效，布尔值使用 `true` 或 `false`（`ture` 会报错并停止清理）。

```dotenv
PHOTO_ARCHIVE_ORIGINAL_DOWNLOAD=false
```

| 配置 | 保存和下载行为 |
|---|---|
| `true` | 新上传和文件夹导入保存原图；大图浏览器和后台显示“下载照片”。有原图则下载原件，无原图则下载现存分辨率最大的展示图。 |
| `false`（默认） | 不保存新原图，隐藏下载入口；`/media/照片ID/download` 与 `/original` 对所有人返回 404。 |

从 `true` 改为 `false` 并重启后，服务会自动在后台检查三档展示图并清理历史原图和旧下载副本，无需另跑命令。首次检查在启动约 1 秒后开始，随后每 30 秒检查并重试；某张照片修复失败时保留其原图，其他照片继续清理。清理会删除原图文件及对应数据库记录，照片信息、系列编排和完整的展示图保留。

从 `false` 改为 `true` 不会恢复已删除的原图。下载时优先使用可读的原件；原图不存在时，在现存展示文件中按像素尺寸选择最大一张，通常为 `lightbox.webp`，大图缺失时继续选择其他可用尺寸。返回真实文件类型、对应扩展名和附件文件名，不会将 WebP 冒充 JPEG。重新上传相同源照片会沿用已有照片记录并补存原件。

公开照片可直接下载，草稿或私有照片只允许管理员下载。下载使用文件流，支持 HEAD 与单段 Range，始终禁止浏览器及 CDN 缓存；开启下载不会公开草稿或私有照片。展示图的缓存规则保持独立。

## 版权元数据

在项目根目录的 `.env.local` 中填写自有照片的作者署名与版权声明，首次配置可复制 `.env.example`。例如填写以下内容。

```dotenv
PHOTO_ARCHIVE_COPYRIGHT_AUTHOR="Your Name"
PHOTO_ARCHIVE_COPYRIGHT_NOTICE="© Your Name. All rights reserved."
```

填写的字段会写入生成的展示图元数据。两项均留空时，展示图不添加本站版权字段。`.env.local` 已被 Git 忽略，GitHub 仓库提供通用的 `.env.example` 模板。

修改后重启服务，新上传照片使用最新配置。对已有照片执行 `npm run media:rebuild`，系统根据配置内容自动判断哪些文件需要更新。

- 三档展示图写入 XMP `dc:creator` 与 `dc:rights`，并保留 ICC 色彩配置。
- 关闭原图下载时原件只在处理期间临时使用；开启时按字节保存并提供原件下载。去重始终依赖数据库中的源文件指纹。
- 标记为示例素材的照片沿用来源作者归属。

`npm run media:rebuild` 会升级历史展示图并按下载开关清理旧媒体文件，不再生成常驻版权下载副本。原图下载提供保存的原件，版权配置用于展示图元数据。版权字段可以被元数据编辑工具修改或删除。

## 本地数据

默认数据目录为 `.data/`，已加入 Git 忽略。

- `archive.sqlite` 保存照片、标签、系列、关联、管理员与会话。
- `media/` 保存不可预测目录名下的三档 WebP Quality 90 展示图；开启原图下载时额外保存 `original`。
- `auth-secret` 保存自动生成的会话签名密钥，文件权限为仅当前用户读写。

数据库启用外键、WAL 和事务。业务结构迁移记录在 `schema_migration` 中，认证表通过 Better Auth 的迁移工具维护。迁移执行由 `db:init` 完成，运行时也会检查业务表结构。

照片下载由 `PHOTO_ARCHIVE_ORIGINAL_DOWNLOAD` 控制；草稿和私有照片的展示图、下载均需要管理员鉴权。展示图保留 ICC 色彩配置并移除 EXIF，页面和照片 API 展示经过挑选的拍摄信息。照片接口使用 `no-store`。公开展示图使用下述 CDN 缓存策略，回源时检查公开状态。草稿、私有展示图和错误响应使用 `no-store`。展示图通过文件流输出，HEAD 请求只返回头部，支持单段 Range 与 206 分段读取。

### 公开展示图 CDN 缓存

网页使用 `/media/照片ID/thumbnail.webp`、`preview.webp`、`lightbox.webp` 三档地址。只有公开照片的这些规范地址允许 CDN 缓存，响应为：

```http
Cache-Control: private, max-age=14400
Cloudflare-CDN-Cache-Control: public, max-age=14400, must-revalidate
```

浏览器和 Cloudflare 均可复用 4 小时内的公开展示图，减少重复下载及通过 Tunnel 回源，以图片加载速度为优先；不启用过期副本兜底。两类缓存通过独立响应头控制，普通响应头中的 `private` 表示仅允许浏览器等私有缓存保存，不代表照片的公开状态；Cloudflare 按专用响应头缓存源站确认为公开的三档展示图。原图下载 `/original`、草稿和私有照片、错误响应、带查询参数的图片请求均不允许 Cloudflare 缓存。旧版无扩展名的展示地址保持兼容，使用浏览器私有缓存及 ETag，每次复用前验证。

Cloudflare 默认识别 `.webp`，因此在默认缓存设置下不必另设“缓存所有内容”规则。需要显式规则时，参考 [精确缓存规则 JSON](docs/cloudflare-cache-rules.json)：仅将三档展示地址标为 Eligible for cache，Edge TTL 选择“有响应头则遵循、无响应头则绕过”，Browser TTL 选择“遵循源站”。另设规则绕过后台、API、原图和下载地址。该文件是供 Cloudflare Cache Rules 使用的配置示例，不会自动修改 Cloudflare 账号；使用其他域名时同步替换其中的主机名。不要强制覆盖源站 TTL 或缓存私有响应。Cloudflare 的 [默认缓存行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/) 和 [规则设置说明](https://developers.cloudflare.com/cache/how-to/cache-rules/settings/) 描述了这些设置。

控制台操作：打开本站域名的 Caching → Cache Rules，新建规则，粘贴 [可直接复制的匹配表达式](docs/cloudflare-public-previews.expression)，将缓存资格设为 Eligible for cache，Edge TTL 设为使用源站响应头、无响应头则绕过，Browser TTL 设为 Respect origin。将该规则置于其他会覆盖这些地址的规则之后。上线时确认公开展示图返回 `Cache-Control: private, max-age=14400`，重复请求可命中浏览器缓存或 Cloudflare `HIT`；Cloudflare 的 `Age` 可用于观察边缘缓存的年龄。缓存到期后可用 ETag 验证未变更的图片，减少重复传输。

**撤回时的失效行为**：照片转为草稿或私有后，源站立即限制访问；已经缓存的公开展示图可在 4 小时有效期内继续复用。Cloudflare 清理不影响访客已经保存的浏览器缓存。配置以下环境变量并重启后，撤回和重建展示图会额外触发精确 URL 清理，以提前使 CDN 副本失效：

```dotenv
PHOTO_ARCHIVE_CLOUDFLARE_ZONE_ID=你的32位ZoneID
PHOTO_ARCHIVE_CLOUDFLARE_API_TOKEN=你的本站缓存清理Token
```

Token 仅需对应 Zone 的 `Cache Purge` 权限；Zone 应覆盖 `BETTER_AUTH_URL` 中的正式域名。密钥只放在服务器环境文件，不要放入前端或 Git。清理任务与数据库更新一起持久化，异步执行、失败重试、重启后恢复；清理三档展示图和历史 grid 地址，不清理原图或下载副本，也不清空整个域名缓存。未配置凭据或清理失败时，仍以 4 小时 TTL 到期为准。清理实现遵循 [Cloudflare 按 URL 清理接口](https://developers.cloudflare.com/api/resources/cache/methods/purge/)。

验证时首次访问可能返回 `CF-Cache-Status: MISS`，同一节点随后应返回 `HIT`；缓存过期后可能为 `REVALIDATED` 或重新取回。原图、下载和私有资源不应出现 `HIT`。

首页查询系列封面，系列详情按 slug 读取当前系列，照片与标签使用批量查询。数据库迁移添加题材分页与系列排序索引。大图组件按需加载，首张照片提高加载优先级，缩放与拖动更新合并到动画帧。

管理员 JSON 请求限制为 4 MiB，照片通过 multipart 流式写入私有临时文件，逐块计算哈希并从文件生成展示图。上传请求按实际字节校验大小，每个进程同时处理最多两次上传。登录限流、来源校验与文件解码校验继续生效。页面添加防嵌入、MIME 嗅探防护、来源策略与限制嵌入对象的安全响应头。

保留整个数据目录可以保留作品和管理员账号。运行中的 SQLite 使用 WAL，后续备份应使用 SQLite 一致性备份方式，或停服后复制整个数据目录。备份恢复演练属于阶段 4。

## PWA 安装与离线提示

站点提供 `/manifest.webmanifest`，安装名称为“片隅”，默认从首页启动，以独立窗口打开。192 / 512 像素安装图标使用暖白不透明背景，另有保留安全裁切区的 Android maskable 图标；Apple 主屏幕图标沿用相同背景。更新 Logo 后运行 `npm run pwa:icons` 重新生成这些图标。

正式使用需要 HTTPS；`localhost` 和 `127.0.0.1` 可用于本机测试。普通局域网 HTTP 地址不能注册 Service Worker，需通过正式 HTTPS 域名安装。页面底部提供“安装片隅”入口：支持原生安装提示的浏览器可直接打开安装窗口，其他浏览器显示菜单操作说明。iPhone / iPad 可在 Safari 分享菜单中选择“添加到主屏幕”，macOS Safari 可使用“添加到程序坞”；具体入口由浏览器提供。独立窗口内隐藏安装入口，安装和离线支持范围取决于浏览器。

生产环境首次访问前台页面后，自动注册 `/sw.js` 并预存自包含的 `/offline.html`、Logo 和安装图标。首次安装需联网并等待资源准备完成；断网后启动应用或完整打开首页、所藏、系列详情时，显示离线提示与重试入口。离线提示页返回 503 和 `noindex`。该版本不提供离线作品浏览：Service Worker 不保存页面 HTML、RSC 数据、照片、下载、API 或后台内容；这些资源继续使用已有的网络和 HTTP 缓存规则。客户端页面切换的数据请求也不写入 PWA 缓存。

网络正常时始终优先请求最新内容，服务器的 401 / 404 / 500 响应保持原样。静态品牌资源联网时更新，离线时可使用缓存。后台和媒体请求不由 Service Worker 接管，登录及私有内容权限校验继续由源站处理；PWA 不扩展原有照片 HTTP 缓存的有效期。

Service Worker 文件禁止浏览器和 Cloudflare 缓存，注册使用 `updateViaCache: none`。新版本下载完成后，在前台页脚提示“新版本已准备好”；点击“更新应用”才激活并刷新当前前台页面，不会主动刷新后台编辑页。更新离线页面或预存资源时，同步递增 `public/sw.js` 中的缓存版本；新 Worker 激活后清理旧的 `pianyu-pwa-` 缓存，保留其他应用的缓存。重新构建并执行 `./restart.sh` 后，可刷新前台页面检查更新。开发模式不注册 Worker，开发和生产建议使用不同端口；已有生产 Worker 不会因为切到开发模式而自动卸载。

验收时可在浏览器开发者工具中确认 Manifest 与 Service Worker 已就绪，再安装应用。离线检查应在 Worker 控制页面后进行，通过完整刷新或重新启动应用确认离线提示。另检查后台、私有照片和下载没有进入 Cache Storage；模拟故障时服务器返回的错误状态不应被离线页替换。检查新版本时保持旧应用打开，发布递增缓存版本的 Worker，再确认更新按钮和手动刷新流程。

## 验证

### 搜索收录与分享预览

正式站点使用 `PHOTO_ARCHIVE_SITE_URL` 作为 SEO 域名，未填写时沿用 `BETTER_AUTH_URL`。例如配置 `PHOTO_ARCHIVE_SITE_URL=https://photos.example.com`；域名必须包含 HTTP(S) 协议，不含路径、查询参数或账号。修改后重新构建并重启。两者均未配置时，页面使用 `noindex`，`robots.txt` 禁止抓取，`sitemap.xml` 为空，避免把本地测试地址提交给搜索引擎。

首页、所藏和系列详情提供独立标题、描述、canonical 规范链接、Open Graph 和 Twitter 大图卡片。题材筛选页统一规范到 `/archive`，`/works` 继续跳转首页。站点提供 WebSite 和系列 ImageGallery 的 JSON-LD；正文中的特殊字符会转义。站点地图仅包含首页、所藏和当前所有成员均公开的已发布系列，不包含后台、草稿或私有照片，也不虚构更新时间。

`/share` 提供 1200 × 630 的品牌分享图；`/share/系列slug` 使用该已发布系列的封面生成同尺寸 JPEG，保留照片完整比例。展示文件缺失时回退到品牌卡片。系列不存在、撤回或包含非公开照片时返回 404。分享图禁止浏览器及 CDN 缓存，输出前会再次校验发布状态；外部社交平台自行保存的预览仍由对应平台刷新。

### 错误恢复与运行监测

页面、后台与根布局异常提供中文恢复界面，支持重试、刷新和返回入口。重试使用当前 Next.js 的 `retry()`，会重新读取并渲染页面。界面仅显示可选问题编号，不展示错误正文或服务器堆栈；后台提示未保存的内容可能需要重新填写。

管理员登录后打开 `/admin/monitoring`，或点击导航中的“运行监测”。页面展示近 7 天 LCP、INP、CLS、FCP、TTFB 的 P75、样本数、按页面汇总和最近 30 条错误。点击“刷新数据”读取最新记录。P75 使用每项指标最终收到的独立样本计算，同一个指标 ID 再次上报时更新值，避免重复计数；各指标样本数不等同于访客数。INP 需要实际交互，部分指标在页面隐藏或离开时才上报，浏览器支持和拦截设置会影响覆盖。普通客户端路由切换沿用文档加载指标归属，只有库提供独立导航归属时才使用对应地址。少量样本仅用于初步观察。

浏览器仅在生产环境上报指标、未捕获脚本异常、未处理的 Promise 异常和页面边界异常。Next.js 服务端请求异常及 API 未预期错误也会记录。数据保存到本站 SQLite 的 `telemetry_event` 表，不发送到第三方；仅保存路由模板、指标值、错误类型、问题编号和接收时间，不保存 IP、Cookie、查询参数、作品名称、错误正文或堆栈。管理页面不计入前台性能分布。原始诊断信息仍可在现有服务日志中查看，错误事件可能来自同一次故障的不同环节。

`POST /api/telemetry` 校验当前来源、字段和实际请求体大小（最大 4 KiB），每个处理进程每分钟最多接收 1200 次请求。浏览器每次文档加载最多上报 10 条错误，并尽可能对同一错误对象去重。记录在写入或查看监测时自动清理，只保留近 7 天且最多 20,000 条；重复指标更新不会刷新最初接收时间。监测失败不会阻断浏览和错误恢复。客户端数据可以被伪造，本地监测用于运行观察，不提供可用率探测、外部报警或跨站用户追踪。
