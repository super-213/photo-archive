## 1. 项目目标与范围

构建一个自有的个人摄影作品集网站：前台以照片为主，采用编辑式极简设计；后台便于上传、整理和策展。内容包括旅行、风光、街拍、人文、汽车和模型/手办摄影。

**核心产品决定**：

1. 前台主导航包含「所见」与「所藏」两个页面。「所见」位于首页 `/`，以**摄影系列**为单位呈现已发布作品。
2. 「所藏」位于 `/archive`，展示全部公开照片，支持按题材筛选。
3. 一张照片可关联多个系列或标签；不重复上传和存储。
4. 单图浏览默认沉浸式深色模式，照片元信息按需展开。
5. 文字少、图片多，以作品集为产品定位。
6. 系列详情保留 `/works/[slug]`，归属「所见」的浏览流程。大图以弹层打开，旧 `/works` 入口跳转首页。

### 1.1 用户角色

- **访客** 浏览「所见」的摄影系列和「所藏」的公开照片，筛选、查看大图与拍摄信息。
- **站点所有者（管理员）**：上传照片，设置公开状态，维护照片元信息、题材标签、摄影系列、封面与排序。

### 1.2 MVP 不做的内容

- 公开注册、用户个人主页和社交关系。
- 点赞、评论、关注、排行榜和商业营销功能。
- 复杂文章编辑器、旅行长文、地图轨迹回放。
- 在线出售照片、下载授权管理、会员订阅。
- 依赖大量 3D / WebGL 的互动特效。

这些能力未来可按实际需求评估，不作为首期负担。

### 1.3 当前实现与本次同步

截至 2026-11-12，阶段 1–3 已完成，并按测试反馈调整了前台布局。当前使用「片隅」品牌，文字标识为「片隅.」，英文副标为「A PERSONAL PHOTOGRAPHY COLLECTION」。已有 18 张示例照片与 3 个示例系列的初始化数据，前台从 SQLite 读取内容。

- 「所见」直接展示系列封面列表，使用编辑式错位栅格，进入详情后可返回所见或继续浏览下一个系列。
- 「所藏」采用响应式瀑布流，桌面四列、中等屏幕三列、手机两列，每批加载 24 张照片。题材入口默认收起，展开后在同一工具行显示选项。
- 顶部导航保留「所见 / 所藏」，系列详情中「所见」保持选中。当前前台布局采用暖白底色、衬线标题与简洁留白。
- 后台保留登录、照片管理、系列管理、新建与编辑流程。系列提供六种布局、分组排序与即时预览。

本次根据路由、组件、样式、数据与媒体服务、部署脚本和现有测试代码同步计划。阶段 1–3 的历史验证记录保留，上线前回归、真实素材、真机和外网验收继续列入待办。

## 3. 页面与业务流程

### 3.1 当前页面与路由

| 路由 | 用途 |
|---|---|
| `/` | 所见，首页与摄影系列列表 |
| `/archive` | 所藏，全部公开照片与题材筛选，使用 `category` 查询参数 |
| `/works/[slug]` | 摄影系列详情，归属所见 |
| `/works` | 旧系列列表入口，跳转 `/` |
| `/admin` | 后台登录，已登录管理员跳转照片管理 |
| `/admin/photos` | 照片上传、元信息与公开状态管理 |
| `/admin/projects` | 摄影系列管理 |
| `/admin/projects/new` | 新建系列 |
| `/admin/projects/[id]` | 编辑系列、封面、布局分组和排序 |

大图由系列详情与所藏共用弹层组件。后台使用独立管理导航。当前站点配置在代码中维护。

### 3.2 访客流程

```text
进入所见 / → 浏览系列封面 → 进入 /works/[slug] → 点击照片打开大图
                          ↑ 返回所见          ↘ 浏览下一个系列

进入所藏 /archive → 展开题材选项 → 选择题材 → 点击照片打开大图
                                  ↘ category 同步 URL，支持刷新、分享和前进后退

大图 → 切图 / 缩放 / 按需展开照片信息 → 关闭后回到原浏览位置
```

### 3.3 管理流程

```text
管理员登录
  → 上传多张照片
  → 解析 EXIF、生成展示尺寸
  → 确认照片标题、日期、地点和标签
  → 设置公开状态
  → 创建/编辑摄影系列
  → 选择封面、加入照片、设定顺序和排版
  → 发布系列
  → 所见展示已发布系列，所藏展示公开照片
```

**安全原则**：上传与发布不应自动混为一步；默认上传后进入草稿或待发布状态，避免未整理照片或隐私元信息意外公开。

## 4. 内容与数据设计

### 4.1 核心实体

当前类型与表结构见 `src/lib/content.ts` 和 `src/lib/server/database.ts`。以下按已落地字段说明，数据库列名使用下划线，业务类型使用驼峰命名。

**Photo（照片）**

- `id`、`digest`、`storage_key` 标识照片、内容摘要与存储位置，重复上传复用已有记录。
- `width`、`height`、`mime_type`、`file_size` 保存图片尺寸与文件信息。
- `title`、`alt`、`description` 保存标题、替代文本与说明。
- `captured_at`、`uploaded_at`、`category`、`year`、`location` 保存日期、题材、年份与人工填写的地点。
- `camera_make`、`camera_model`、`lens_model`、`focal_length`、`aperture`、`shutter_speed`、`iso` 保存基础 EXIF。
- `visibility` 使用 `draft | public | private`，`version` 用于并发编辑检查。
- `source`、`is_sample` 标记示例素材与来源。

**MediaVariant（媒体资源）**

- `photo_id`、`variant`、`filename`、`mime_type`、`encoding_version` 关联上传源图、展示图与编码策略版本。
- 当前尺寸类型为 `original`、`download`、`thumbnail`、`preview`、`grid`、`lightbox`。`original` 用于存档与去重，`download` 保存自有照片的版权副本。访客下载公开照片的原尺寸版权副本，草稿和私有照片需管理员授权。

**Project（摄影系列）**

- `id`、`slug`、`title`、`subtitle`、`description`、`cover_photo_id`。
- `year`、`category`、`sort_order`、`published_at`。
- `status` 使用 `draft | published`，`version` 用于并发编辑检查。

**ProjectPhoto（系列与照片的关联）**

- `project_id`、`photo_id`、`sort_order`、`layout_type`、`layout_group`、`caption`。
- 支持一张照片归属多个系列，排序与布局按系列分别保存。
- `layout_group` 保存显式布局分组，同类型相邻组可以独立维护，兼容旧数据的布局编排。

**Tag / PhotoTag（标签）**

- 标签表使用 `id`、`name`，关联表使用 `photo_id`、`tag_id`。
- 题材使用照片的 `category` 字段，前台所藏按题材筛选。自定义标签可在后台编辑并在照片信息中展示。

封面裁切焦点、稳定单图页面 URL 等可选能力留待后续按需评估。

### 4.2 数据约束

1. 系列与照片必须通过关联表维护，禁止为每个系列复制一份照片实体。
2. 只有 `public` 照片允许进入所藏，系列发布时必须检查关联照片的公开状态。
3. 所有源文件路径使用不可预测存储 Key；私有文件访问须由服务端授权，不可仅靠“隐藏 URL”。
4. 网页展示图移除 EXIF，保留 ICC 色彩配置。照片 API 隐藏 GPS，公开原尺寸下载副本保留拍摄元数据并写入本站版权声明。
5. 管理员手动修改的日期、地点、器材信息不得被后续重复解析覆盖。

## 5. 当前技术实现

阶段 1–3 已按以下方案落地，缓存、外网部署与恢复能力在阶段 4 继续验收。

| 层级 | 当前选型 | 用途 |
|---|---|---|
| 前端框架 | Next.js + TypeScript | 路由、SEO、图片展示和后台可共用项目 |
| 样式 | CSS Variables + 原生 CSS | 统一设计 Token、编辑式栅格与响应式布局 |
| 动效 | CSS 淡入、Web Animations API、Pointer Events | 连续响应手势，支持减少动态效果偏好 |
| 数据库 | SQLite（本地文件） | 配合本地部署，启用外键、WAL 和事务 |
| 数据访问 | better-sqlite3 + 参数化 SQL | 版本化迁移与事务维护照片、系列及多对多关系 |
| 媒体存储 | 本地私有目录 + 鉴权媒体路由 | 媒体按照片可见性检查权限，原图完整保存，展示图独立生成 |
| 图片处理 | Sharp + exifr | 生成 420 / 840 / 1440 / 2560 像素边界内的 无损 WebP 展示图并提取 EXIF |
| 管理员认证 | Better Auth，关闭公开注册 | 使用数据库会话与登录限流，管理员通过本地命令创建 |
| 部署 | 本地 Next.js 服务 + Cloudflare Tunnel | 已确认本地运行，启动端口由站点所有者手动指定 |

**部署决定（2026-11-11）**：本地运行，通过 Cloudflare Tunnel 转发，端口手动指定。预计照片数量、单张文件大小、访客地域和预算仍待确认，这些信息会影响媒体分发、带宽与备份方案。

### 5.1 媒体处理流水线

```text
原始上传文件
  ├── 元数据读取（EXIF；GPS 默认隐藏）
  ├── 校验文件类型与尺寸、必要的安全检查
  ├── 生成 thumbnail（小图）
  ├── 生成 grid / card（中等尺寸）
  ├── 生成 lightbox（高清展示版）
  └── 保留上传源图（公开照片供访客下载）
```

当前按显示尺寸选择派生图并保留尺寸占位，大图采用缩略预览过渡到清晰图。网站保存上传的高分辨率 JPG 等原文件，RAW 备份留待后续评估。HEIC 转换需验证当前 Sharp 运行环境的支持情况。

### 5.2 画质、大文件与原图下载

当前实现已调整为三档 WebP Quality 90（最长边 420、840、2560 像素），原图仅用于内部存档和重建。前台、后台下载按钮和原图 HTTP 下载接口均已关闭。以下为早期方案与验收记录。

按 2026-11-12 的新决定，展示图使用 WebP 无损编码，尺寸分别为最长边 420、840、1440、2560 像素。无损编码保留缩放后的像素，缩小分辨率会减少细节。ICC 配置随展示图保留，上传原文件逐字节保存。

单张上传支持 256 MiB、最多 2.4 亿像素，采用 multipart 流式写入临时文件、文件哈希与文件输入的图片处理流程。已有照片通过 `npm run media:rebuild` 从原图升级展示图，数据库版本 4 添加编码版本字段，原图与人工编辑数据保留。

公开照片在大图弹层提供“下载原图”，返回原尺寸版权下载副本，包含拍摄元数据、ICC 与本站版权声明。草稿和私有照片需管理员登录，公开状态在每次下载前检查。原图使用附件响应与 `no-store`，支持 Range 分段读取。水印后续应用于展示图。

严格无损编码产生的展示文件可能比此前有损 WebP 更大，浏览器按显示尺寸选择较小档位，并使用缩略预览与条件请求。当前 18 张样例的缩略图中位体积约 140 KiB，最大大图约 4.3 MiB。

已重建 18 张既有照片的展示图并核对原图 SHA-256。通过 81 MiB 测试文件的 HTTP 上传、完整原图下载与分段读取，以及 1.2 亿像素 JPG 和 ICC 保留测试。手机视口在 400 KB/s、150 ms 延迟模拟中完成展示图与大图加载，普通浏览原图请求数为 0。真实作品的观看效果与真实弱网体验继续验证。

### 5.3 版权元数据

版权署名与声明通过项目根目录 `.env.local` 中的 `PHOTO_ARCHIVE_COPYRIGHT_AUTHOR` 与 `PHOTO_ARCHIVE_COPYRIGHT_NOTICE` 配置。仓库的 `.env.example` 提供空白模板，本地配置按 Git 忽略规则管理。自有照片的展示图写入已配置的 XMP 字段，JPEG 和 TIFF 下载副本同时写入相应 EXIF 字段。

配置随服务启动读取。两个字段都留空时使用上传原件下载，配置变更后运行 `media:rebuild` 更新已有照片。版权副本与展示图的版本标识根据配置内容自动计算。

版权写入采用 ExifTool 元数据编辑，JPEG 图像压缩数据经过逐字节比对。存档原件用于上传哈希与去重，版权下载副本的文件哈希随元数据变化，额外占用接近一份原图的空间。系统需要 Perl。

样例素材沿用来源作者归属。`media:rebuild` 升级历史内容，旧下载首次访问时可补齐版权副本，生成过程使用临时文件、原子替换与单照片并发合并。元数据版权声明可被编辑或清除。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图片体积过大 | 页面慢、带宽成本高 | 派生图、响应式图片、缓存、延迟加载 |
| 排版过度自由 | 后台难维护、不同尺寸失控 | 使用现有六种布局、分组容量约束与即时预览 |
| 相册数据不断增长 | Archive 浏览性能下降 | 分页/增量加载、索引、缩略图 |
| EXIF 包含 GPS | 隐私泄露 | 展示图与 API 隐藏坐标，原图公开范围由所有者确认 |
| 自托管访问不稳定 | 海外/不同网络访问体验不一致 | 部署前测试目标访客网络，媒体分发与前端解耦 |
| 过度追求动效 | 牺牲图片质量与可访问性 | 以基础功能和性能指标为优先，动画后置 |

## 11. 产品决策与待确认事项
