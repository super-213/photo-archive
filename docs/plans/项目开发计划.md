## 1. 项目目标与范围

构建一个自有的个人摄影作品集网站：前台以照片为主，采用编辑式极简设计；后台便于上传、整理和策展。内容包括旅行、风光、街拍、人文、汽车和模型/手办摄影。

**核心产品决定**：

1. `Works` 以**摄影系列**为单位呈现精选作品。
2. `Archive` 展示全部公开照片，支持按题材筛选。
3. 一张照片可关联多个系列或标签；不重复上传和存储。
4. 单图浏览默认沉浸式深色模式，照片元信息按需展开。
5. 文字少、图片多，以作品集而非博客为产品定位。

### 1.1 用户角色

- **访客**：浏览主页、摄影系列与公开档案；筛选、查看大图与拍摄信息。
- **站点所有者（管理员）**：上传照片，设置公开状态，维护照片元信息、题材标签、摄影系列、封面与排序。

### 1.2 MVP 不做的内容

- 公开注册、用户个人主页和社交关系。
- 点赞、评论、关注、排行榜和商业营销功能。
- 复杂文章编辑器、旅行长文、地图轨迹回放。
- 在线出售照片、原图下载授权、会员订阅。
- 依赖大量 3D / WebGL 的互动特效。

这些能力未来可按实际需求评估，不作为首期负担。

## 3. 页面与业务流程

### 3.1 页面路由（建议）

```text
/                    首页
/works               精选摄影系列列表
/works/[slug]        摄影系列详情
/archive             照片档案（筛选条件放到查询参数）
/admin               管理后台入口（需认证）
/admin/photos        照片管理
/admin/projects      摄影系列管理
/admin/settings      站点设置（可选）
```

### 3.2 访客流程

```text
进入首页 → 查看精选摄影系列 → 进入某个系列 → 浏览摄影作品 → 点开全屏大图
                                          ↘ 展开 EXIF 信息（可选）
进入 Archive → 选择题材筛选 → 打开单张照片 → 返回筛选结果
```

### 3.3 管理流程

```text
管理员登录
  → 上传多张照片
  → 解析 EXIF、生成展示尺寸
  → 确认照片标题、日期、地点和标签
  → 设置公开状态
  → 创建/编辑摄影系列
  → 选择封面、加入照片、设定顺序和排版
  → 发布系列
  → 前台 Home / Works / Archive 自动展示对应内容
```

**安全原则**：上传与发布不应自动混为一步；默认上传后进入草稿或待发布状态，避免未整理照片或隐私元信息意外公开。

## 4. 内容与数据设计

### 4.1 核心实体

**Photo（照片）**

- `id`, `storageKey`, `slug`（若需要稳定单图 URL）
- `width`, `height`, `orientation`, `mimeType`, `fileSize`
- `capturedAt`, `uploadedAt`, `title`, `description`
- `cameraMake`, `cameraModel`, `lensModel`, `focalLength`, `aperture`, `shutterSpeed`, `iso`
- `country`, `city`, `locationLabel`（位置需人工确认）
- `visibility`：`draft | public | private`
- `coverFocalPoint`（可选，供封面裁切使用）
- `variants`：缩略图、网格图、大图等关联资源

**Project（摄影系列）**

- `id`, `slug`, `title`, `subtitle?`, `coverPhotoId`
- `year?`, `locationLabel?`, `category?`
- `status`：`draft | published`
- `featuredOrder`, `publishedAt`

**ProjectPhoto（系列与照片的关联）**

- `projectId`, `photoId`, `sortOrder`, `layoutType?`, `caption?`
- 支持一张照片归属多个系列；排序属于“系列中的照片”，不属于照片本身。

**Tag / PhotoTag（标签）**

- 标签表：`id`, `name`, `slug`, `type`（如题材标签）
- 关联表：`photoId`, `tagId`

### 4.2 数据约束

1. 系列与照片必须通过关联表维护，禁止为每个系列复制一份照片实体。
2. 只有 `public` 照片允许进入公开 Archive；系列发布时必须检查关联照片的公开状态。
3. 所有源文件路径使用不可预测存储 Key；私有文件访问须由服务端授权，不可仅靠“隐藏 URL”。
4. EXIF GPS 默认不公开，并在图片导出/处理时有明确剥离或保护策略。
5. 管理员手动修改的日期、地点、器材信息不得被后续重复解析覆盖。

## 5. 技术实现建议（可调整）

以下是适合个人项目的参考方案，**不是强制选型**。

| 层级 | 优先建议 | 理由 |
|---|---|---|
| 前端框架 | Next.js + TypeScript | 路由、SEO、图片展示和后台可共用项目 |
| 样式 | CSS Variables + 原生 CSS | 统一设计 Token、编辑式栅格与响应式布局 |
| 动效 | CSS 淡入、Web Animations API、Pointer Events | 连续响应手势，支持减少动态效果偏好 |
| 数据库 | SQLite（本地文件） | 配合本地部署，启用外键、WAL 和事务 |
| 数据访问 | better-sqlite3 + 参数化 SQL | 版本化迁移与事务维护照片、系列及多对多关系 |
| 媒体存储 | 本地私有目录 + 鉴权媒体路由 | 原图与私有照片按请求检查权限，展示图独立生成 |
| 图片处理 | Sharp 或对象存储/CDN 的图片处理能力 | 生成不同尺寸、格式和缩略图 |
| 管理员认证 | Better Auth，关闭公开注册 | 使用数据库会话与登录限流，管理员通过本地命令创建 |
| 部署 | 本地 Next.js 服务 + Cloudflare Tunnel | 已确认本地运行，启动端口由站点所有者手动指定 |

**部署决定（2026-11-11）**：本地运行，通过 Cloudflare Tunnel 转发，端口手动指定。预计照片数量、单张文件大小、访客地域和预算仍待确认，这些信息会影响媒体分发、带宽与备份方案。

### 5.1 媒体处理流水线

```text
原始上传文件
  ├── 元数据读取（EXIF；GPS 默认隐藏）
  ├── 校验文件类型与尺寸、必要的安全检查
  ├── 生成 thumbnail（小图）
  ├── 生成 grid / card（中等尺寸）
  ├── 生成 lightbox（高清展示版）
  └── 保留原图（仅管理员访问；是否保留 RAW 另行决定）
```

需要按设备尺寸响应式加载图片，指定尺寸并优先使用浏览器支持的高效格式。不可把全部 RAW / 原始 JPEG 直接推送到访客端。原图是否允许公开下载应独立配置，默认关闭。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图片体积过大 | 页面慢、带宽成本高 | 派生图、响应式图片、缓存、延迟加载 |
| 排版过度自由 | 后台难维护、不同尺寸失控 | 限定 4–5 种基础布局，并提供预览 |
| 相册数据不断增长 | Archive 浏览性能下降 | 分页/增量加载、索引、缩略图 |
| EXIF 包含 GPS | 隐私泄露 | 默认不公开位置坐标、必要时清理元数据 |
| 自托管访问不稳定 | 海外/不同网络访问体验不一致 | 部署前测试目标访客网络，媒体分发与前端解耦 |
| 过度追求动效 | 牺牲图片质量与可访问性 | 以基础功能和性能指标为优先，动画后置 |

## 11. 待确认的产品决策

这些问题**不阻碍先开发前台静态原型**，但进入后台与部署阶段前需要确定：

- **部署方式（已确认）**：本地运行，通过 Cloudflare Tunnel 转发；启动端口由站点所有者手动指定。
- **存储范围**：网站只存展示用 JPEG/HEIC 转换图，还是连 RAW 原片一并备份？A: 网站只存展示用 JPEG/HEIC 转换图
- **公开范围**：Archive 是公开作品全集，还是包含仅本人可见的私人档案？当前方案默认为“仅公开照片对访客可见”。A:仅公开照片对访客可见
- **体量与预算**：预计起步照片数、单张大小、月增长量、访问区域与流量。
- **版权策略**：是否显示版权说明、添加水印、是否允许下载展示图。A:显示版权说明、添加水印、允许下载展示图
- **管理方式**：后台网页上传，还是未来增加从本地文件夹自动同步。

## 12. 完成定义（Definition of Done）

当以下条件全部满足时，可认为首个正式版本完成：

- 访客能够在 Home → Works → Project 中顺畅浏览摄影系列。
- 访客能够在 Archive 中按题材查找公开照片。
- 所有公开照片均可进入沉浸式大图查看。
- 管理员可以独立完成上传、整理、创建系列、排序与发布。
- 同一照片无需重复存储即可关联多个系列。
- 横图、竖图、不同题材的图片在移动端与桌面端显示合理。
- 非公开内容、管理员入口与敏感 EXIF 得到恰当保护。
- 图片加载性能经过真实网络测试，数据库和原图具备可验证的恢复途径。
